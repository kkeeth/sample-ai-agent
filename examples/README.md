# 作例3本

`src/tools.ts` にそのまま入る、動くツール一式です。**丸ごとコピーして、そこから壊していくのがいちばん速い**です。

```bash
cp examples/doc-agent/tools.ts src/tools.ts
bun run agent "経費精算の締め切りはいつ?" -v
```

戻したくなったら、別の作例を上書きコピーするだけです。`git checkout src/tools.ts` で骨組みにも戻せます。

---

## どれを選ぶか

エージェントが触る「外の世界」は、だいたいこの3つのどれかです。作りたいものがどれに近いかで選んでください。

| 作例 | 外の世界 | 副作用 | こういうものを作るなら |
| --- | --- | --- | --- |
| [`doc-agent`](doc-agent/tools.ts) | ローカルのファイル | 書き込み1つ（承認あり） | 社内資料の横断検索、ログの一次調査、コードベースへの質問 |
| [`http-agent`](http-agent/tools.ts) | HTTP API | なし（読むだけ） | 社内APIやSaaSを叩く、複数サービスを横断する |
| [`state-agent`](state-agent/tools.ts) | JSONファイル上の状態 | 書き込み2つ（承認あり） | 予約、申請、チケット起票、在庫、なんらかの手続き |

**2つ以上を混ぜて構いません。** むしろ実物はたいてい混ざります（社内資料を読んで → APIを叩いて → 起票する、など）。
`tools` 配列を連結して、`runTool` の `switch` に case を足すだけです。

---

## それぞれ何を見せているか

### `doc-agent` — ローカルのファイルを読む

`workspace/docs/` の社内資料を調べて答えます。テンプレートの元になっていた作例です。

見どころ:

- `search_files` → `read_file` の順に呼ばせるための description の書き方
- `safePath()` で `workspace/` の外を触らせない
- `clip()` で戻り値を切る（外すと長いファイルを読んだ瞬間にコストが跳ねる）

### `http-agent` — HTTP を叩く

GitHub の公開 API を叩きます。認証は不要（未認証は 60 回/時）。

見どころ:

- **JSON をそのまま返さない。** 要る列だけ残して1件1行にしてから返す
- **失敗を throw しない。** 404 なら「search_repos で探し直せ」、レート上限なら「もう呼ぶな」と文章で返す。モデルは次の周回でそのとおりに動く
- 引数の検証はこちら側でやる。モデルは平気で `number: "abc"` を入れてくる

> ⚠ この作例はネットワークが通らない環境では動きません。会場の回線で1回試してから配ってください。

### `state-agent` — 状態を書き換える

会議室の予約エージェント。3本のうち、これだけが「読む」で終わりません。

見どころ:

- 状態を変えるツールは `WRITE_TOOLS` に入れる。名前を足すだけで実行前に承認が入る
- **書き込みの前に、こちら側で必ず検証する。** モデルが「空きを確認しました」と言っていても信用せず、二重予約はコード側で弾く
- 拒否されたとき・矛盾したときに、何が起きたかを文章で返す

状態は `workspace/state/bookings.json` に保存され、実行をまたいで残ります。実務ではここが DB や社内システムの API になります。

## 中身の構造は3本とも同じ

```ts
export const SYSTEM_PROMPT = `...`;              // ① 役割と方針
export const tools: Anthropic.Tool[] = [ ... ];  // ② 名簿。モデルが読むのはここだけ
export const WRITE_TOOLS = new Set([ ... ]);     // 承認を挟むツールの名前
export async function runTool(name, input) {}    // ③ 中身。ただの関数
```

この4つを export していれば、ループ側（`src/agent.ts`）は何も変えなくて動きます。
